## 4. Test Strategy Recommendations

### 4.1 Test Levels

| Level | Scope | Tools | Coverage Target |
|-------|-------|-------|-----------------|
| **Unit Tests** | Business logic (services, matcher, point calc) | Go `testing` + `testify` | ≥ 80% on service layer |
| **Integration Tests** | API endpoints + database | Go `httptest` + test PostgreSQL | All 4 endpoints + webhook |
| **E2E Tests** | Full flow (webhook → matching → scoreboard) | Docker Compose + test scripts | Happy path + key edge cases |
| **Manual Tests** | streamer.bot integration, Cloudflare Tunnel | Live environment | Per-stream verification |

### 4.2 Test Data Strategy

| Data Type | Source | Notes |
|-----------|--------|-------|
| Subscribers | Seed data (DB Schema §7) | 3 test subscribers |
| Donations | Seed data (DB Schema §7) | 4 test donations (3 matched, 1 unmatched) |
| YouTube API | Mock responses | Unit tests use mock HTTP client |
| EasyDonate API | Mock responses | Unit tests use mock HTTP client |
| Webhook payloads | Fixtures | Valid + invalid signature test cases |

### 4.3 Critical Test Scenarios (from ACs)

| AC ID | Scenario | Test Type | Why Critical |
|-------|----------|-----------|--------------|
| AC-001c | Upsert (re-subscriber) | Integration | Core data integrity |
| AC-001d | Both sources capture same subscriber | Integration | Timestamp preservation logic |
| AC-020b | Idempotent sync (duplicate donation) | Integration | Prevents double-counting points |
| AC-021a | Exact match (case-insensitive) | Unit | Core matching logic |
| AC-021c | Anonymous donation | Unit | Edge case — must not award points |
| AC-022d | Only matched donations count | Integration | Points accuracy |
| AC-031c | 0-point viewers excluded | Integration | New requirement from design |
| HMAC | Webhook signature verification | Unit | Security — fake donation prevention |
